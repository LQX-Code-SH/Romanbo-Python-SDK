# 证据日志

本目录存放真机联调时由 [`tools/servo_probe.py`](https://github.com/LQX-Code-SH/Romanbo-Python-SDK/blob/main/tools/servo_probe.py)
采集的**原始探针日志**（请求 / 应答的逐字节十六进制记录）。

协议文档中以「日志证明……」表述的结论即引用这些文件——保留原始字节是为了让结论**可被独立复核**。

## 文件命名

```
probe-<日期>-<时刻>.log        例如 probe-20260925-221313.log
```

采集环境：两个 MOS 系列舵机串联（ID 8 / ID 10）挂在 `COM3`（FTDI FT230X），
115200 8N1，2026-09-25。

## 主要用途

### 1. 位置限值的成因定案

| 日志 | 时刻 | ID 10 的 `0x1A` 回包 | 限值 |
|---|---|---|---|
| `probe-20260925-221313.log` | 22:13:13 | `00 00 01 03 FF` | **(1, 1023)** |
| `probe-20260925-221625.log` | 22:16:25 | `00 00 FF 03 00` | **(255, 768)** |

两条记录相隔 3 分钟，中间窗口内**没有任何写帧**（只有读命令与一条 `SET_TORQUE`），
共同说明：位置限值是**可写配置**，而非型号出厂差异；且成因是**不带数据的 `0x0F`**
会被固件当成 `SetPositionLimit`、用解析缓冲残值改写限值。

详见 [协议规格 §6](../SERVO_SPEC.md) 与 [§11 本版本纠正的旧结论](../SERVO_SPEC.md)。

### 2. 应答延迟与总线静默期

早期把「应答慢」归因于舵机延迟，日志显示真实原因是**寻址到无设备 ID 之后的静默期**。
结论与实测阈值见 [协议规格 §3](../SERVO_SPEC.md)。

## 新增证据

新采集的日志默认写入仓库根目录下的 `logs/`（已被 `.gitignore` 忽略）。若某次联调结论
需要长期留存，请：

1. 把相关日志复制到本目录（保留 `probe-<日期>-<时刻>.log` 命名）；
2. 在本文件或 [协议规格](../SERVO_SPEC.md) 中写明它证明了什么结论。
