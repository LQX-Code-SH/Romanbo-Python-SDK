# 安全与已知限制

## 会动真机，请注意

- 所有运动类命令（`jog` / `angle` / `sweep` / `move` / `play`）**会立即驱动舵机**；
  下肢 / 悬臂场景请先做好支撑。
- 参数类命令（`pid` / `limit` / `param` / `margin` / `calib` / `set-id` / `reset`）
  会**写入舵机内部并掉电保存**，建议先 `config` 记下原值。
  **`SET` 类命令没有 ACK**，写入可能被静默丢弃，所以 `pid` / `limit` 默认回读确认
  （依据见[实测结论](FINDINGS.md)）。
- `torque off` 后关节会失去保持力（下肢关节会失去支撑而倒下）。
- `param period`、`param current-limit`、`param accelerate` 三项**效果无法确认**
  （分别被固件忽略、写入后无法回读），请勿依赖。

## `0x0F` 绝对不要发送

`0x0F` 与 `SetPositionLimit` 同码，**任何情况下都不要发送**：它**不带数据**也会把缓冲里
残留的 4 字节当成 min/max 写进限值（现场记录见[实测结论 §7](FINDINGS.md)）。

库层已上保险：

- `Servo.get_period()` 默认**抛 `ProtocolError` 拒发**，只有显式 `get_period(unsafe=True)` 才会发送
- `tools/servo_probe.py` 也把它移出默认清单（需 `--unsafe-0f`）

## 明确不支持 / 未验证的清单

| 项目 | 状态 |
|---|---|
| 力矩闭环 / 设定「目标力矩值」 | ❌ 协议中不存在 |
| 出力档位（H/M/L/W） | ✅ 可用（`0x09` 的 `d[5]` bit3-4，`--level`） |
| 电流环 / 电流限流 | ⚠️ `0x0D` 写入无法回读，效果未验证 |
| 运动周期调速（`SET_PERIOD`） | ❌ 固件忽略 |
| 多关节预置 + 同步触发（`0x21`+`0x20`） | ❌ 不响应 |
| 读加速度（`0x19`） | ❌ 无应答 |
| 保存式 PID 写入（`0x07`）是否落盘、开机载入 | ⚠️ 即时生效不稳定（库改为先发 `0x47`）；落盘/载入未验证（需真断电） |
| 舵机 `GetModel`/`GetVersion` | ❌ 属控制器帧（ID0），需要控制器板才有应答 |
| 空转 FreeWheel | ⚠️ `0x21` 位域无法验证；`SET_WHEEL(free=1)` 效果未观测 |
| 控制器板全部命令 | ⚠️ 未验证（需要控制器板） |
| 改波特率 / 改 ID / 复位 / 零点校准 | ⚠️ 已封装，未做破坏性验证 |

## 软件层面的边界

- **不要用多个线程同时驱动动作**：`_io_lock` 串行化了「发—等」，但 `play` / `move`
  在两线程下会逐帧交错，动作被打乱（见[安装与环境](INSTALL.md)「并发边界」）。
- 连续下发时仍**偶发丢包** → `get_*` 默认重试 2 次；批量探测语义见
  `RomanboRobot.capture(retries=)`（丢包量级见[实测结论](FINDINGS.md)）。
- 软件限力只能「尽早停」，**不是力矩上限**：传感器是实测负荷，存在采样延迟，
  阈值要留余量，见[软件限力](LOAD_LIMITING.md)。
