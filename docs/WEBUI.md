# 可视化控制台

一个**只监听本机**的 Web 界面：扫描舵机、实时读数、单/多关节运动、参数读写，
并把**原始收发报文**实时打在页面上。

## 快速开始

```bash
python -m romanbo webui --mock                  # 模拟器：无需硬件（17 个虚拟舵机）
python -m romanbo webui --port /dev/ttyUSB0     # 真机（Windows 用 --port COM3）
python -m romanbo webui --port COM3 --open      # 启动后自动打开浏览器
```

终端会打印一条**带令牌的链接**：

```
ROMANBO 舵机控制台已启动，请用浏览器打开：
  http://127.0.0.1:8765/?token=rMzwI2ab3GhaVcn4As1KOA
```

浏览器打开即可。链接里的令牌是本次会话的访问凭据，**不要转发给别人**。

| 选项 | 说明 |
|---|---|
| `--http-host` | 监听地址，默认 `127.0.0.1`（只监听本机回环） |
| `--http-port` | 端口，默认 `8765`；`0` = 由系统分配 |
| `--open` | 启动后自动打开浏览器 |
| `-p/--port` | 串口（与其它子命令一致）；给了就**自动连接** |
| `--mock` | 模拟模式，完全不碰硬件 |

## 为什么这样设计

- **零新依赖**：服务端只用标准库（`http.server` / `json` / `threading` / `secrets`），
  页面是单个内联 HTML（无 CDN、无框架）。运行期依赖仍然只有 pyserial。
- **只监听回环 + 访问令牌 + Host 校验**：这是个能驱动硬件的服务，即使在本机也不该
  被任意网页调到（CSRF / DNS rebinding）。绑定到非回环地址时 Host 校验会失效，
  此时**令牌是唯一防线**，不要暴露到公网。
- **报文日志抓在传输层**：TX 必为整帧、RX 为本轮读到的字节，与真机串口助手看到的
  一致，可直接按[字节级规格](SERVO_SPEC.md)对照。
- **高频轮询只走轻量读数**：页面上按 0.7 s 轮询的只有「位置 / 负荷 / 温度」，
  而且单次超时、不重试；完整参数只在选中舵机或手动「重读全部参数」时取，
  避免把总线占满、把运动节拍拖慢。

## 界面能力

| 区域 | 能做什么 |
|---|---|
| 顶栏 | 枚举/选择串口、连接与断开、扫描在线舵机（1..32）、**紧急停止** |
| 在线舵机 | 列表（显示最近读到的 ADC），点选切换控制对象 |
| 实时读数 | 位置 ADC / 角度 / 实测负荷 / 温度 / PID / 位置限位 |
| 运动控制 | 滑块与角度双输入；「平滑运动」走步进逼近（给速度）、「立即到位」最大速度；±10°、回中位；限力阈值与负荷检查间隔；出力档位 H/M/L/W；力矩使能/断开 |
| 多关节 | 每个在线舵机一根滑块，「全部平滑到位」一次下发（走 `robot.move`） |
| 参数写入 | PID / 位置限位 / Margin / **LED（8 色可选：灭/红/绿/蓝/黄/紫/青/白）** / 零点校准，**写入后回读确认**，失败会报错 |
| 报文日志 | TX/RX 原始十六进制 + 命令码名，可暂停 / 清空 / 自动滚动 |

## HTTP 接口

所有 `/api/*` 都需要令牌（请求头 `X-Robot-Token`，或查询参数 `?token=`）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 连接状态、在线列表、最近错误 |
| GET | `/api/ports` | 枚举串口与占用情况 |
| GET | `/api/frames?since=N` | 增量取报文（`N` = 已取到的最大 `seq`） |
| GET | `/api/servo/{id}` | 完整参数（含换算角度） |
| GET | `/api/servo/{id}/live` | 轻量读数：位置 / 负荷 / 温度 |
| GET | `/api/capture` | 批量回读位置 |
| POST | `/api/connect`、`/api/disconnect` | `{port, mock, baudrate}` |
| POST | `/api/scan` | `{start, end}` |
| POST | `/api/servo/{id}/goto` | `{adc\|angle, speed_dps, max_load, level, load_check_every}` |
| POST | `/api/servo/{id}/torque`、`/pid`、`/limit`、`/margin`、`/calib` | 见界面 |
| POST | `/api/servo/{id}/led` | `{red, green, blue}`（推荐）或 `{value}`（低 3 位 = 红/绿/蓝）；响应含**实际下发的 `d[5]`** |
| POST | `/api/move` | `{targets:{id:adc}, speed_dps, max_load, level, load_check_every}` |
| POST | `/api/stop_all` | 对所有在线舵机断开力矩（未扫描时向 1..32 广播） |

失败一律返回 `{"error": "..."}`：软件限力中止是 **409 + `aborted: true`**（并带
`detail`），未连接 / 参数非法是 409，舵机无应答是 504。

## 真机验证记录（2026-09-27）

环境：两个 MOS 舵机（ID 8 / ID 10）串联在 `/dev/ttyUSB0`（FT230X），115200 8N1。

只读部分：

| 项 | 结果 |
|---|---|
| 扫描 1..32 | `found=[8,10]`，16.2 s（与 CLI 一致） |
| ID 8 / ID 10 参数 | 位置 512、PID 100/1/20、限位 (1,1023)、margin 5、calibration 116（偏置 −12）、温度 34 / 37 ℃、负荷 0 |
| 报文逐字节 | 探询 `FF FF 08 06 05 EF` / `FF FF 0A 06 05 ED`；回包 `FF FF 08 07 85 00 6E` / `FF FF 0A 07 85 00 6C`（后者与 `golden.py` 中 9-25 真机采集的向量一致）；`FF FF 08 0A 92 00 64 01 14 E5` → PID 100/1/20，与解析值互相印证 |

运动部分：

| 项 | 结果 |
|---|---|
| 单关节 512 → 600 @30°/s（不限力） | ✅ 9 步到位 **599**（误差 1 ADC ≈ 0.3°） |
| 多关节 8→530 / 10→492 @30°/s | ✅ **两个关节都到位**（531 / 492）——`MIN_FRAME_GAP` 修复的端到端回归 |
| 回到中位 | ✅ 8: 513 / 10: 511 |

LED 八色（同一环境，逐帧核对 `docs/SERVO_SPEC.md` §5.4）：

| 下发 | 线上帧（ID 8） | `d[5]` |
|---|---|---|
| 红 `(1,0,0)` | `FF FF 08 07 11 80 62` | `0x80` ✅ |
| 蓝 `(0,0,1)` | `FF FF 08 07 11 20 C2` | `0x20` ✅ |
| 紫 `(1,0,1)`／旧写法 `value=5` | `FF FF 08 07 11 A0 42` | `0xA0` ✅ |
| 灭 `(0,0,0)` | `FF FF 08 07 11 00 E2` | `0x00` ✅ |

### 顺带测到一个重要事实：起步冲击

按文档原先的建议把限力阈值取 60，30°/s 的运动**在起步第 1 步就被中止**（实测负荷 85）；
改 80 仍中止（第 1 步 **147**）；改成 100 且把**负荷检查间隔调到 3** 才顺畅走完
（采样峰值 81）。

原因：`load_check_every=1` 时第一次负荷采样正落在**加速涌流**上，那不是卡死。所以控制台
的默认是**限力关闭**，界面里直接标注实测区间。取舍与用法见[软件限力](LOAD_LIMITING.md)。

## 已知限制

- 模拟器只能演示流程：动作瞬间到位、负荷恒为 0，**不能**用来验证限力与速度精度。
- 界面不做动作排队：一次运动请求在返回前会占住设备锁（长距离慢速运动需要等
  `距离 / 速度` 秒），期间其它请求排队等待。
- 没有用户体系与多客户端隔离：它是**单人本机调试工具**，不是生产控制台。
- 与 `0x0F` 相关的能力一律不暴露（该命令会改写位置限位，见[安全与已知限制](SAFETY.md)）。
